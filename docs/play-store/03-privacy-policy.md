## 3. Data we collect and process

Depending on how your school configures Gurukull and which features you use, the following categories may be processed:

### 3.1 Account and authentication data

- Registered **mobile number** and **password** (password is transmitted for authentication; we do not display your password in the App)  
- Parent profile details returned by the school platform (for example name, email if stored by the school)  
- **Authentication token** stored on your device after login  
- **Device identifier** generated by the App and stored on the device to support **single-device / session** login controls (for example a locally created ID such as an app-generated device string, sent as `device_id` / device name during login)

### 3.2 Child / student school data (viewed by parents)

Data the school has linked to your parent account for one or more children, which may include:

- Student name, class/section, and identifiers used by the school  
- Attendance  
- Homework and assignments  
- Exams and marks  
- Timetable, class events, discipline records  
- Fee-related information published to parents  
- Leave applications and statuses  
- Notices, calendar events, magazine or school information content  
- Staff directory information exposed to parents  
- Lesson plans or online class listings when published  
- School transport / trip status and related location updates **as provided by the school platform** (the current React Native App does not request the parent phone’s GPS permission solely to power this screen)

### 3.3 Messages and communications

- Chat messages and chat room metadata with school staff or admin  
- Emergency / broadcast school mail or alerts from school administration  
- Feedback you submit to the school (category and message text)

### 3.4 Device and app preferences

- Theme preference (light / dark / system) stored on the device  
- Selected child identifier stored on the device for convenience  
- Standard technical communication needed to call the API (for example HTTPS requests)

### 3.5 Crash, diagnostics, and logs

The current Eklavya React Native build does **not** ship a separate third-party crash analytics SDK by default. Server or hosting logs on Gurukull may still record technical events (for example API request metadata, timestamps, and error responses) as part of operating the platform. If crash or analytics tools are added later, this policy will be updated and Play Console Data safety disclosures will be revised.

### 3.6 Data we do not intentionally collect via this App build

Based on the current React Native `AndroidManifest` (internet access only):

- The App does **not** request camera, microphone, contacts, SMS, or precise device location permissions  
- The App does **not** use your Google account for sign-in; login is school-issued mobile + password  

(If you use a different native sibling build with additional permissions, see that build’s store listing and policy addendum.)

## 4. How we use data

We process personal data to:

- Authenticate you and maintain a secure session  
- Enforce single-device / concurrent login rules using the device identifier  
- Display school information for the children linked to your account  
- Enable leave applications, feedback, and messaging with the school  
- Remember your selected child and display preferences on your device  
- Operate, secure, and troubleshoot the Gurukull parent services  
- Comply with applicable law and respond to lawful requests  

We do **not** sell parent or student personal data.

## 8. Retention

- **On device:** Session token, selected child, theme, and device ID remain until you log out, clear app data, or uninstall. Logging out clears session-related keys used by the App.  
- **On the school platform:** Retention follows the **school’s** and Gurukull platform’s record-keeping practices (academic year archives, fee records, message history, etc.).  
- **Account deletion:** The App does not independently erase school master records. To deactivate a parent login or remove access, **contact your school administrator** (and optionally support@gurukull.in). Schools control whether a parent mobile number remains authorised.

---

## 9. Security

We use industry-standard measures appropriate to a school parent client, including:

- HTTPS / TLS for API traffic in production  
- Bearer token authentication after login  
- On-device storage limited to session and preference data  
- Application backup disabled (`allowBackup="false"`) in the React Native Android configuration  

No method of transmission or storage is 100% secure. Protect your password and do not share OTP or credentials. If you suspect unauthorised access, change your password and ask the school to revoke other device sessions.

---

## 10. Children’s data

Eklavya is designed for **parents and guardians (adults)**. It may display **personal data about minors** (students) because the school has linked those records to the parent account.

- We do not knowingly allow children to create parent accounts through this App.  
- Parents should use the App only for children for whom they are authorised guardians.  
- Schools remain responsible for verifying parent–student relationships and for decisions about what student data is exposed to parents.

If you believe a child’s data is shown to the wrong parent account, contact the school immediately.
